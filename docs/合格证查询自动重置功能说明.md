# 合格证查询自动重置功能说明

## 问题描述

原有的查询流程用户体验不佳：

1. 选择筛选条件
2. 点击"添加条件"
3. 选择统计维度
4. 点击"开始查询"
5. 查看结果
6. **第二次查询前需要手动点击"重置所有条件"** ❌

这导致用户点击频率过高，使用周期过长。

## 解决方案

**实施方案一：查询后自动重置**

查询成功后自动执行以下操作：

- 自动重置 `CertificateSearchConditions` 组件的条件表单
- 自动清空 `CertificateSelectedConditions` 组件中的已选条件列表
- 保留查询结果供用户查看

## 修改内容

### 1. CertificateSearchConditions.vue

**修改位置：** `frontend/src/components/CertificateSearchConditions.vue`

**修改内容：**

- 在 `<script>` 标签末尾添加 `defineExpose`，暴露 `handleReset` 方法给父组件调用

```typescript
// 暴露方法给父组件调用
defineExpose({
  handleReset,
});
```

### 2. CertificateQuantity.vue

**修改位置：** `frontend/src/views/CertificateQuantity.vue`

**修改内容：**

1. 添加组件引用：

```typescript
// 组件引用
const searchConditionsRef =
  ref<InstanceType<typeof CertificateSearchConditions>>();
```

2. 在模板中绑定 ref：

```vue
<certificate-search-conditions ref="searchConditionsRef" ... />
```

3. 在 `handleSearch` 方法的查询成功后添加自动重置逻辑：

```typescript
if (response.code === 200) {
  tableData.value = response.data.list;

  ElMessage.success(`查询完成，共找到 ${response.data.total} 条记录`);

  // 查询成功后自动重置条件表单和清空已选条件
  // 这样用户可以直接添加新条件进行下一次查询，无需手动点击重置
  if (searchConditionsRef.value) {
    searchConditionsRef.value.handleReset();
  }
  // 清空已选条件
  selectedConditions.value = [];
}
```

## 用户体验改进

### 优化前的流程：

1. 选择条件 → 添加条件
2. 选择维度 → 开始查询
3. 查看结果
4. **点击"重置所有条件"** ⬅️ 额外步骤
5. 重复步骤 1-4

### 优化后的流程：

1. 选择条件 → 添加条件
2. 选择维度 → 开始查询
3. 查看结果
4. **直接选择新条件 → 添加条件 → 开始查询** ✅ 无需手动重置

## 功能特点

✅ **自动重置**：查询成功后自动清空条件表单和已选条件  
✅ **保留结果**：查询结果保留在页面上供用户查看  
✅ **减少点击**：用户无需手动点击"重置所有条件"按钮  
✅ **快速查询**：可以立即添加新条件进行下一次查询  
✅ **保留手动重置**：用户仍可使用"重置所有"按钮手动清空所有内容

## 问题修复记录 (2025-12-26)

### 导出功能异常修复

**问题现象：**
在实施自动重置功能后，导出功能（导出当前页、导出全部）出现数据范围错误。即使用户设置了筛选条件（如"上海大众"），导出的数据却是全量数据。

**原因分析：**
查询成功后，`selectedConditions` 被清空（自动重置逻辑）。随后点击"导出"按钮时，导出函数直接读取了已被清空的 `selectedConditions`，导致向后端发送的查询参数中不包含任何过滤条件，从而导出了全量数据。

**修复方案：**
1. 新增 `lastSearchConditions` 变量，用于持久化存储最后一次成功查询的条件。
2. 在 `handleSearch` 成功后，先将当前条件深拷贝备份到 `lastSearchConditions`，再执行清空操作。
3. 修改所有导出函数 (`handleExport`, `handleExportAll`, `handleExportData`)，将其依赖的数据源从 `selectedConditions` 改为 `lastSearchConditions`。

**修改代码：**

```typescript
// 1. 新增状态变量
const lastSearchConditions = ref<any[]>([])

// 2. 修改 handleSearch
if (response.code === 200) {
  // ...
  // 保存当前查询条件用于导出功能
  lastSearchConditions.value = JSON.parse(JSON.stringify(conditions))
  
  // 原有的清空逻辑
  selectedConditions.value = []
}

// 3. 修改导出函数 (示例)
const handleExport = async () => {
  // ...
  const params = {
    ...buildSearchParams(lastSearchConditions.value), // 使用备份的条件
    // ...
  }
  // ...
}
```

## 测试建议

1. **基本查询流程测试**

   - 添加查询条件
   - 选择统计维度
   - 点击"开始查询"
   - 验证查询结果显示正常
   - 验证条件表单已自动重置
   - 验证已选条件列表已清空

2. **连续查询测试**

   - 完成第一次查询
   - 直接添加新的查询条件（无需手动重置）
   - 点击"开始查询"
   - 验证第二次查询正常执行

3. **导出功能测试 (重点)**

   - 添加特定筛选条件（如特定企业）并查询
   - 点击"导出当前页"或"导出全部"
   - **验证导出的Excel文件中数据是否仅包含筛选后的企业数据**
   - 验证导出并未因为自动重置而变成全量导出

4. **手动重置测试**

   - 添加查询条件
   - 点击"重置所有"按钮
   - 验证所有条件和结果都被清空

5. **查询失败场景测试**
   - 添加查询条件
   - 模拟查询失败（如网络错误）
   - 验证条件表单和已选条件是否保留（失败时不应重置）

## 注意事项

- 只有在查询**成功**时才会自动重置，查询失败时保留条件供用户修改
- 查询结果会保留在页面上，用户可以继续查看或导出
- 用户仍可使用"重置所有"按钮手动清空所有内容（包括查询结果）
- 统计维度选择不会被重置，用户可以继续使用相同的维度进行查询
